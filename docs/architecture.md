# Architecture and reference semantics

Reference: adjacent Python checkout `vo_regular_bp`, specifically context.py,
acceptors.py, product_bp.py, constraints.py and constraint_builders.py; tiny
exactness, optimization and numerical robustness tests; optimization example;
paper experiment README and https://arxiv.org/html/2605.07839v1 (sections 2–5).

A context is a sequence of symbols before emission. Training counts each token
at every available suffix order, without joining separate sequences or adding
termination tokens. Normalize each row independently. After emission, select
the longest known suffix within maxOrder. Explicit missing rows are dead ends.
This is a fixed stochastic source, not a generation-time order-stack policy.

Symbols are strings or finite numbers, encoded to integer IDs. Context IDs are
interned encoded tuples. DFA states are strings or finite numbers; null rejects.
Composite constraints intern tuples to integer states. Final acceptance is Boolean,
with unit terminal weight. Optional transition weights are nonnegative finite
factors; zero removes support. Factors are logged separately to avoid underflow.

Compile only horizon-reachable pairs (contextId, dfaStateId), caching outgoing
rows. Layers retain integer IDs; backward values are Float64Arrays indexed within
each sparse layer. beta[n,q] is terminal acceptance; beta[t,q] is the sum of
edge weight times beta[t+1,next]. We compute this recurrence in log space always,
sacrificing some speed for a single stable numerical path. Ordinary mass is exp(logZ)
and can underflow without implying infeasibility. Sampling uses normalized future
mass. Conditional probability uses the same product paths. Max-plus DP uses strict
comparison, preserving first outgoing edge on computed ties, as Python does.

Diagnostics distinguish unique pairs from time-indexed states and edges. Empty
horizons, absent continuations, rejected transitions and zero mass are explicit.
Infeasible sampling/probability raises; optimization returns explicit infeasibility.
Exactness means the supplied finite model conditioned on acceptance, subject to
floating-point arithmetic; it is not an exact-real optimality certificate.

Core has no platform imports. Constraints depend only on core. One npm package
exposes core and constraints subpaths; separate scoped packages can follow later.
Browser playground imports emitted ESM in a Worker. No UI framework or runtime
package dependency. Golden fixtures serialize explicit graph and DFA tables and
are generated by unmodified Python, with independent enumeration for tiny models.
MAXORDER forbids training substrings of length limit+1; strict training at order
limit can therefore be infeasible. Text novelty examples use a lower source order.
